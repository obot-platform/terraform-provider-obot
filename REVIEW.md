# Review notes

- **Start a catalog source edit's timeout only after it holds the client's catalog lock.** Every `obot_mcp_catalog_source` in an apply shares one client, and each edit waits for a full catalog sync. A deadline that also counts time queued behind other sources makes later sources time out, before their write, with an error unrelated to them. The lock wait itself must end when the context does. `ModifyCatalogSources` owns both; resources must not wrap it in their own timeout.
- **Never let a catalog entry update erase what the resource does not model.** Obot's entry `PUT` replaces the whole manifest, keeping only `toolPreview` and `staticConfigurationRevision`, so a field `obot_mcp_catalog_entry` drops on read is deleted from Obot on the next apply with nothing in the plan. `CatalogEntryDefinition.Unmodeled` lists such content: Read only warns about it, so plan and destroy keep working, and Update re-reads the entry and refuses to replace it. When the resource starts modeling a field, add it to the modeled sets in `internal/client/catalog_entry.go` in the same change; when Obot adds a manifest field, it is refused until modeled.
- **Check the recorded header value revision before any catalog entry write that sends a header as stored.** A header sent with `static: true` and no value keeps whatever Obot holds, and the response's new `staticConfigurationRevision` is then recorded in private state, so a value changed in the Obot UI after the plan's refresh would be kept and its drift hidden for good. `update` re-reads the entry and, when the revision differs from the recorded one, sends every header's configured value instead.
- **Give every client type that holds a secret a redacting `String` and `GoString`, including types nested in a manifest.** `%v` formats nested structs field by field, so one `%+v` of a manifest in a diagnostic, log, or test failure prints any token or header value it carries. `Tunnel`, `GitCredentialManifest`, `CatalogEntryConfig`, and `CatalogEntryManifest` follow this; add the methods when a new type gains a secret field.
- **Strip credentials from any server-reported URL before it reaches a diagnostic.** Obot accepts catalog source URLs with a Git token as userinfo and copies them onto entries, and `Client.Redact` only catches 80-character runs, which a GitHub token is not. Format such URLs with `client.DisplaySourceURL`, and pass any written to state, such as `obot_mcp_catalog`'s, through `client.StripURLCredentials`, which removes userinfo and redacts query values (a `private_token` or presigned signature works as a credential), then redact the raw URL and the credentials it returns from server messages that repeat them. Stripped URLs can collide, so merge values rather than overwrite, and dedupe sets. Never strip URLs sent back to Obot: `obot_mcp_catalog_source` writes the full source list, and a stripped URL there would drop its credentials.
